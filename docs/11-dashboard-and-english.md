# Phase 11：首頁總覽與英文介面

## 首頁總覽（`/`）

登入後第一個畫面。每個區塊依使用者的權限顯示，金額只給有財務權限的人看。

| 區塊 | 內容 | 權限 |
|---|---|---|
| 今天要處理 | 需要處理的訂單商品、待對應 SKU 的 Whatnot 商品、超過 2 天沒寄出的已付款訂單、逾期的入庫包裹、待核准盤點、已到最晚下單日的 SKU、需要確認的 Whatnot 財務交易、超過 6 小時沒同步；每一項都直接連到處理的頁面 | 依項目 |
| 本週 | 成交額、售出件數、訂單、直播場數；和**上週同樣天數**比較（不是拿未過完的這週和完整的上週比） | `orders.view`（金額另需財務權限） |
| 最近 8 週 | 成交額（或件數）長條圖 | `orders.view` |
| 本月損益 | 淨銷售額、毛利、營運費用、淨利，以及是否完整 | `finance.view` |
| 最近的直播 | 最近 14 天的直播，含毛利 | `finance.view_livestream` |
| 庫存 | 美國可售、運送中、缺貨 SKU 數；有成本權限才顯示成本 | `inventory.view` |

所有數字都由各明細頁使用的同一套計算產生，所以和明細頁一定一致。原本的「庫存總覽」移到 `/inventory`。

## 英文介面

- **切換方式**
  - 「我的帳號 › 介面語言」：繁體中文 / English。選擇會**存在帳號上**，換手機或電腦登入也一樣。
  - 登入頁右上角也可以先切換。
- **預設語言**：還沒登入時，依這台瀏覽器上次的選擇；沒選過就依瀏覽器語言。
- **翻譯範圍**：全部畫面，約 930 段文字，包括：
  - 錯誤訊息
  - 圖表說明
  - 補貨建議的算式說明
  - 費用類別、物流商名稱
- **日期格式**：跟著語言（英文：11/10/2026）；金額一律為 $1,234.50。

### 怎麼做的（給維護的人）

- 程式裡的中文就是翻譯的鍵，例如 `t("已寄出 {0} 件", [n])`；英文放在 `frontend/src/locales/en.ts`。
- 伺服器送來、需要翻譯的說明（例如補貨建議的備註）以 `{key, args}` 傳送，英文寫在 `en.ts` 的伺服器區段。
- 費用類別與物流商名稱也在 `en.ts` 翻譯。
- `npm run i18n:check`：檢查每一段中文都有英文、`{0}` 等參數一致、沒有用不到的翻譯。**新增畫面文字後請執行。**
- 自動化測試 `e2e/phase11.cjs`：切到英文後逐一打開 13 個主要頁面，確認畫面上沒有殘留中文介面文字。商品名稱、直播標題、使用者輸入的內容本來就是原文，不在檢查範圍。

### 目前還是中文的部分

系統自動產生的**細節文字**仍是中文。介面上的類別標籤（例如「出貨時庫存不足」）已經翻成英文，有需要再改成可翻譯的格式。這些細節包括：
- 訂單例外細節，例如「已出貨但美國倉帳上庫存不足：…」
- Whatnot 財務交易的檢查說明
- 帳本備註

## 資料庫變更

無。使用者的語言存在既有的 `users.locale`，可選 `zh-TW`、`en-US`；新增 API `PUT /api/v1/auth/me/preferences`。
