# Phase 6：單場直播損益

## 目的

算出每一場直播**實際賺多少**，而不是只看銷售額。

## 數字從哪裡來

全部從帳本（`financial_entries`）讀取，報表和帳永遠一致；不使用任何估計值或費率推算。

| 項目 | 來源 |
|---|---|
| 商品銷售額、優惠券 | Whatnot 訂單（Phase 5） |
| Whatnot 佣金（含稅）、金流手續費（含稅）、賣家付的運費 | Whatnot 財務報表 `seller_financial_report` 的 `ORDER_EARNINGS` |
| 退款、退款運費、申訴退回、物流商調整、小費 | 財務報表其他交易類型 |
| 商品成本 | 採購批次先進先出，出貨時認列（Phase 5） |
| 直播時長、觀眾、買家、點擊率 | Whatnot 直播數據 `/analytics/shows/{id}`（只用來對照，不進帳） |

**毛利 = 銷售額 − 優惠券 − 退款 − 佣金 − 手續費 − 賣家運費 − 商品成本 + 小費**（營運費用在 Phase 7 扣除）。

## Whatnot 財務報表（官方文件確認，2026-11-09）

- `POST /reports` 申請 → 非同步產生 → 下載 CSV（一筆帳務交易一列，以 `ledger_transaction_id` 識別）
- 已用業主帳號驗證（7 天、1,194 列）：
  - 每筆訂單恰好一筆 `ORDER_EARNINGS`
  - 每一列都符合：入帳金額 = 成交價 − 佣金 − 佣金稅 − 手續費 − 手續費稅 − 賣家運費
- 14 天實測：2,378 筆交易，0 錯誤
  - 系統已有的 1,088 筆訂單：ERP 營收與 Whatnot 成交價 **全部一致**
  - 每場直播「扣平台費用後」與 Whatnot 預估收入一致（$2,014.25、$2,355.70、$2,587.68、$1,677.20）

### 怎麼入帳

| 交易類型 | ERP |
|---|---|
| `ORDER_EARNINGS` | 佣金、手續費、賣家運費（**不重複認列營收**，營收來自訂單本身） |
| `ORDER_REFUND` | 全額退款：退回商品金額 ＋ 沖回該訂單的手續費；其他退款：以 Whatnot 扣回的淨額入帳 |
| 運費類（`SHIPPING_CHARGE`、`CARRIER_ADJUSTMENT`…） | 賣家運費；退回的部分記為運費調整 |
| `APPEALED_ORDER_REFUND` | 退款調整（申訴成功，錢退回） |
| `TIP` | 其他收入 |
| 未知類型、非 USD、金額正負號不合理 | 保存但不入帳，列為「需要確認」 |

- **不重複**：每筆交易只入帳一次。API 每次同步回看 14 天、報表重疊、或 CSV 與 API 都進來同一筆，都不會重複
- **ERP 沒有的訂單**（例如系統上線前的訂單）：先保存不入帳；訂單同步進來後自動補上
- **金額不變**：交易一旦保存，金額由資料庫觸發器鎖定；之後的報表若給了不同數字，標示「金額被更改」並保留原數字，請人工確認
- **費用日期**：跟著訂單日期（和營收同一個月）；若那個月已結帳，改記在交易完成日
- **隱私**：買家名稱、州、國家、商品描述不讀取也不保存；報表下載連結不帶 API 金鑰、不寫入日誌，下載後立即處理、不留檔
- 報表還在產生時不會卡住同步：下次同步會接著處理

## 數字不完整時

報表**不會用估計值補**，而是明確標示：

- 「N 筆手續費未到」：Whatnot 通常在出貨後才把該筆訂單寫進財務報表
- 「N 件成本未認列」：還沒出貨
- 「N 件需處理」：待對應 SKU、庫存不足等（Phase 5 的例外清單）

## 畫面

- **直播損益**（側邊欄、手機底部列）：期間內每場的淨銷售額、Whatnot 費用、商品成本、毛利、毛利率、每小時毛利、完整度
- **單場明細**：
  - 損益明細、與 Whatnot 數字對照、觀眾數據
  - **各商品**：整筆訂單的費用依商品金額比例分攤；未對應的商品依名稱（去掉 #編號）合併成一列
  - 退款與需要確認的交易、手續費還沒到的訂單
- **訂單頁**：選擇直播後可直接連到該場損益
- **Whatnot 串接頁**：財務報表交易（已入帳／訂單不在系統／需確認）
- **試算表匯入 › Whatnot 財務報表（CSV）**：API 無法使用時的備援，格式與 API 報表相同

權限：`finance.view_livestream`（管理員、美國直播營運、台灣管理人員）。
