# Phase 9：物流

## 目的

業主的流程是「日本買了直接寄美國」（不經過日本倉）。這個階段讓每一個寄出的包裹都可以：
- 追蹤
- 分次簽收
- 記錄短少或損壞

同時處理三件相關的事：
- 量出實際交期（Phase 10 補貨要用）
- 列出美國還沒寄給買家的訂單
- 讓所有庫存損耗正確反映在損益表上

## 入庫包裹（日本 → 美國）

| 步驟 | 誰 | 系統做什麼 |
|---|---|---|
| **建立寄出包裹**（採購批次頁） | `shipment.manage_jp` | 選這次要寄的商品和數量、物流商、追蹤號碼、箱數。每個採購項目建立一個先進先出批次（落地成本），放在「運送中」。**運送中不算美國可售** |
| **更新追蹤資訊** | 日本或美國人員 | 補追蹤號碼、改預計到貨日 |
| **簽收**（物流 › 包裹頁） | `shipment.receive_us` | 每個商品填「收到」和「短少／損壞」。收到的立刻變成美國可售；短少要填原因；沒填的留在運送中，之後再簽收 |

- **包裹編號**：`P<寄出日>-<序號>`，例如 `P261105-01`。
- **預計到貨日**：寄出日 ＋ 規劃交期，可以手動改。超過預計到貨日還沒收完，就標示「逾期 N 天」。
- **物流商**：日本郵便 EMS、國際小包、FedEx、DHL Express、UPS、USPS、ヤマト國際宅急便；有追蹤號碼就直接連到物流商的追蹤頁。
- **防止錯誤**
  - 寄出數量不能超過採購數量（所有項目都先檢查，任何一項超過，整個包裹都不建立）。
  - 簽收數量不能超過運送中的數量。
  - 連按兩次只會處理一次。
- **紀錄**：每個包裹都有寄出、更新、部分簽收、全部到貨的紀錄，只能新增不能修改。
- **Phase 9 之前用舊方式**（按採購項目）寄出的貨，仍在採購批次頁按項目簽收。用包裹寄出的，一律在包裹頁簽收，兩邊不會重複。

## 實際交期

已全部到貨的包裹，寄出到全部收完的天數：平均、中位數、最長（最近 180 天），和規劃交期並列。

## 美國待出貨

- 列出已付款、還沒離開美國倉的 Whatnot 訂單，下單超過 2 天標紅。
- 判斷依據是 Whatnot 自己的出貨狀態（已交寄、運送中、已送達才算寄出），所以還沒對應 SKU 的商品也判斷正確。
- **用真實資料發現並修正 Phase 5 的同步缺口**
  - Whatnot 在包裹已經寄出後，訂單狀態仍是 `pending_fulfillment`。
  - 原本同步只會重新讀取「已預留庫存」的商品的出貨狀態，未對應 SKU 的商品永遠看起來沒寄出。
  - 現在每次同步都會重新讀取所有已付款、尚未完成的訂單的出貨狀態。
- **中斷的同步**：伺服器重啟時被中斷的同步，下次同步會標示為「已中斷」，不會一直顯示「進行中」。

## 存貨損耗計入損益（修正）

原本損壞報廢、盤點短少、庫存調整只減少庫存，**沒有反映在損益表**，會讓毛利看起來比實際高。現在每一筆都依該批次的先進先出成本自動入帳：

| 庫存異動 | 損益 |
|---|---|
| 損壞報廢、庫存調整減少、盤點短少、運送短少 | 存貨損耗（負數） |
| 庫存調整增加、盤點多出 | 盤盈（正數） |
| 期初庫存、拆盒、顧客退貨 | 不影響損益 |

- 損益表新增「存貨損耗／盤盈」一列，計入毛利。
- 已結帳月份的異動記在當月，並註明原本的月份。
- 這次更新也會補記之前已經發生的損耗。

## API

| 端點 | 權限 |
|---|---|
| `GET /api/v1/carriers` | `inventory.view` |
| `GET /api/v1/parcels?status=open/received/all`、`GET /api/v1/parcels/{id}` | `inventory.view`（成本另需成本權限） |
| `POST /api/v1/parcels`（Idempotency-Key） | `shipment.manage_jp` |
| `PATCH /api/v1/parcels/{id}` | `shipment.manage_jp` 或 `shipment.receive_us` |
| `POST /api/v1/parcels/{id}/receive`（Idempotency-Key） | `shipment.receive_us` |
| `GET /api/v1/logistics/lead-time` | `inventory.view` |
| `GET /api/v1/logistics/outbound-backlog` | `orders.view` |

## 資料庫變更（0013）

- `shipment_lines.purchase_line_id`：一個包裹可以有同一個 SKU 的不同採購批次
- `inventory_lots.shipment_line_id`：每個批次記得是哪個包裹寄來的
- `shipments.idempotency_key`、`packages`（箱數）
- 物流商資料（含追蹤網址）
- `financial_entries` 新增可正可負的類型 `inventory_adjustment`，並補記既有的損耗
